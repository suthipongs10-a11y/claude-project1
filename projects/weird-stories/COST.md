### 🔑 เพิ่ม key ใหม่แล้วต้องรันคำสั่งนี้ก่อนเสมอ

```bash
python3 tools/check_keys.py
```

มันจะยิงทดสอบทีละ key แล้วบอกว่าตัวไหนทำอะไรได้ (text / เสียง / ภาพ / batch)
พร้อมบันทึกผลไว้ให้ `gemini_api.py` เลือก key ให้ตรงงานโดยอัตโนมัติ:

```
งานเสียง -> key ฟรีก่อน   (เก็บเครดิตของ key ที่เสียเงินไว้ทำภาพ)
งานภาพ   -> key ที่เสียเงินเท่านั้น (free tier ทำภาพไม่ได้ ยิงไปก็เสียเวลาเปล่า)
```

ถ้าไม่รันคำสั่งนี้ ระบบจะหมุน key ไปเรื่อยๆ ซึ่งงานเสียงอาจไปตกที่ key ที่เสียเงิน
ทั้งที่มี key ฟรีว่างอยู่ และงานภาพอาจเสียเวลายิงใส่ key ฟรีที่ทำไม่ได้อยู่แล้ว

คำสั่งนี้ยัง **ปลดสถานะ "ใช้ไม่ได้" ให้ key ที่เพิ่งเติมเครดิต** ด้วย
(ไม่งั้นระบบจะจำว่ามันตายไปอีก 6 ชั่วโมง)

### 💡 ทางประหยัดที่ดีที่สุดที่เจอ: เสียงไม่ต้องเสียเงินเลย

key #3 เป็น free tier ซึ่ง **เรียก TTS ได้ฟรี** ทดสอบแล้วทั้ง `gemini-2.5-flash-preview-tts`
และ `gemini-3.1-flash-tts-preview` ตอบ HTTP 200 ปกติ (ที่ใช้ไม่ได้บน free tier คือ "ภาพ" กับ "batch")

`gemini_api.py` จำไว้แล้วว่า key ไหนเครดิตหมด และข้ามไปใช้ key ที่ยังไหวโดยอัตโนมัติ
→ **งานเสียงทั้งหมดวิ่งไปที่ key ฟรีเอง ค่าเสียงจึงเป็น 0 บาท**
(อัดเสียงใหม่ทั้ง 20 ท่อนของ ep00 = ฟรี)

จึงไม่ต้องเปลี่ยนโมเดล TTS ไปหาตัวที่รองรับ batch อีกต่อไป — ของฟรีถูกกว่าส่วนลด 50% อยู่แล้ว
และได้ใช้ `gemini-2.5-flash-preview-tts` ที่ภาษาไทยเสถียรที่สุดต่อไปด้วย

### สถานะ Batch API: ✅ ใช้งานได้จริงแล้ว

ทดสอบในไปป์ไลน์จริงแล้ว — สร้างภาพใหม่ 4 ใบผ่าน batch สำเร็จ ที่เหลือ 36 ใบหยิบจากแคช
```
หยิบจากแคช 36 ภาพ (ไม่เสียเงิน)
ต้องสร้างใหม่ 4 ภาพ (Batch API ราคาครึ่งเดียว)
  v27b, v30c, v30d, v31b -> สำเร็จทั้งหมด
```
เวลารอ: 4 ภาพราว 4-5 นาที, 1 ภาพราว 4 นาที (มีค่าคงที่ของการเข้าคิวอยู่)

## 1. แคชแบบ content-addressed — ประหยัดได้มากที่สุด ✅ ใช้งานได้แล้ว

`tools/cache.py` เก็บผลลัพธ์ทุกอย่างที่เสียเงินเรียก โดยใช้ **sha256 ของอินพุตเป็นชื่อไฟล์**

```
เสียง  key = sha256(model + voice + style + ข้อความ)
ภาพ    key = sha256(model + prompt + aspect)
เพลง   key = sha256(model + prompt)
```

**ผลที่ได้จริง (ทดสอบแล้ว):** ลบโฟลเดอร์ `audio/` กับ `images/` ของ ep00 ทิ้งทั้งหมด แล้วรันใหม่

```
gen_voice   18 ท่อน  หยิบจากแคชหมด  0.29 วินาที  ไม่เสียเงิน
gen_images  35 ภาพ   หยิบจากแคชหมด  0.08 วินาที  ไม่เสียเงิน
```

ก่อนมีแคชงานเดียวกันนี้ใช้เวลา ~11 นาที และเสียเงินเต็มจำนวน

**ข้อดีที่มากกว่าการเช็คว่า "มีไฟล์ชื่อนี้อยู่ไหม" แบบเดิม:**
- ลบไฟล์ในโปรเจกต์ทิ้ง → ยังไม่ต้องจ่ายซ้ำ
- ย้าย segment / เปลี่ยนชื่อ id → ยังไม่ต้องจ่ายซ้ำ เพราะ key มาจากเนื้อหา ไม่ใช่ชื่อ
- **แก้ prompt ของช็อตเดียว → สร้างใหม่เฉพาะช็อตนั้น** (แบบเดิมจะไม่สร้างใหม่เลย ซึ่งผิด)
- ใช้ prompt ซ้ำข้ามตอน → จ่ายครั้งเดียว

**เสียงเก็บเป็น FLAC** — lossless แต่เล็กกว่า WAV ราว 48% (ep00: 13.3 MB → 6.9 MB)
ตรวจแล้วว่า decode กลับมาได้ **ตรงกันทุก sample**

### ที่เก็บ

```
local   $WS_CACHE_DIR  (ค่าเริ่มต้น ~/.cache/weird-stories)  — อยู่นอก repo
remote  S3-compatible (R2 / B2 / S3)                        — ถ้าตั้ง env ไว้
```

แคชอยู่นอก repo ตามที่ตั้งใจ เพราะมันโตขึ้นเรื่อยๆ ทุกตอน ส่วน repo ต้องเล็กพอที่จะ clone เร็ว

ดูสถานะแคช: `python3 tools/cache.py`
เอาของเก่าที่ทำไว้แล้วใส่เข้าแคช: `python3 tools/cache_backfill.py episodes/<ep>`

### ตั้งค่าซิงก์ขึ้น R2 / B2

```bash
export WS_CACHE_S3_BUCKET=weird-stories-cache
export WS_CACHE_S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com   # B2 ใช้ https://s3.<region>.backblazeb2.com
export WS_CACHE_S3_ACCESS_KEY=...
export WS_CACHE_S3_SECRET_KEY=...
export WS_CACHE_S3_REGION=auto        # R2 ใช้ auto, B2 ใช้ชื่อ region
```

ไม่ต้องซิงก์ทั้งก้อนก่อน/หลังทำงาน — เพราะ key คำนวณล่วงหน้าได้ ระบบจึงดึงเฉพาะไฟล์ที่ต้องใช้จริง
(local ไม่มี → ลอง remote → ไม่มีอีกค่อยเรียก API แล้วอัปกลับขึ้น remote) ประหยัด bandwidth กว่าซิงก์ทั้งโฟลเดอร์

> ⚠️ **ตอนนี้ environment บล็อกโดเมนของ R2 กับ B2 อยู่** — ทดสอบแล้ว gateway ตอบ 403 ตอน CONNECT
> ```
> r2.cloudflarestorage.com    ❌ 403
> *.backblazeb2.com           ❌ 403
> s3.amazonaws.com            ✅ ผ่าน
> ```
> ต้องเพิ่มโดเมนพวกนี้ใน network policy ของ environment ก่อน
> (ดู https://code.claude.com/docs/en/claude-code-on-the-web) หรือใช้ AWS S3 ซึ่งผ่านอยู่แล้ว
> ระหว่างที่ยังไม่ได้ตั้ง remote ระบบจะใช้แคช local อย่างเดียวโดยไม่ error

## 2. Batch API — ลด 50% ตรงๆ ✅ ใช้งานได้แล้ว

`tools/gemini_batch.py` ส่งงานทั้งชุดเข้าคิวแทนการยิงทีละใบ ราคาครึ่งเดียว

```bash
python3 tools/gen_images.py episodes/<ep>/shots.json          # batch (ค่าเริ่มต้น)
python3 tools/gen_images.py episodes/<ep>/shots.json --now    # ทีละใบ เต็มราคา
```

**เหมาะกับงานนี้มาก** เพราะภาพและเสียงทั้งคลิปถูกสร้างจนครบก่อนเริ่มเรนเดอร์อยู่แล้ว
ไม่มีขั้นตอนไหนต้องรอผลทีละใบแบบโต้ตอบ

**เวลารอ (วัดจริง):** 1 ภาพ ~4 นาที, 4 ภาพ ~4-5 นาที — เวลาส่วนใหญ่เป็นค่าคงที่ของการเข้าคิว
ยิ่งส่งเป็นชุดใหญ่ยิ่งคุ้ม (Google การันตีแค่ว่าเสร็จภายใน 24 ชั่วโมง แต่จริงเร็วกว่านั้นมาก)

**ผลพลอยได้:** โหมด batch ไม่ต้องหน่วง 8 วินาทีต่อภาพเพื่อกัน rate limit เหมือนโหมด `--now`
→ 35 ภาพประหยัดเวลารอไปอีกราว 5 นาที

### เสียงไม่ต้องใช้ batch — เพราะมันฟรีอยู่แล้ว

`gen_voice.py` รองรับ batch อยู่ (ใส่ `"model"` ใน `script.json` เป็น `gemini-3.1-flash-tts-preview`
หรือ `gemini-2.5-pro-preview-tts` แล้วมันจะเปิดโหมด batch ให้เอง) แต่**ไม่จำเป็นต้องใช้**
เพราะงานเสียงวิ่งไปที่ key free tier ซึ่งฟรีเต็มจำนวนอยู่แล้ว ถูกกว่าส่วนลด 50%

ข้อดีที่ตามมาคือได้ใช้ `gemini-2.5-flash-preview-tts` ที่ภาษาไทยเสถียรที่สุดต่อไป
โดยไม่ต้องแลกน้ำเสียงกับส่วนลด

## 3. อย่างอื่นที่ทำไปแล้ว

- **สลับภาพส่วนใหญ่มาใช้ `gemini-3.1-flash-image`** แทน `gemini-3-pro-image`
  เทียบด้วย prompt เดียวกันแล้วแทบแยกไม่ออก แต่ถูกกว่ามาก
  เก็บ pro ไว้แค่ 6 ช็อตสำคัญ (ฮุกเปิด ตัวละครหลัก จุดพีค ปิดคลิป)
- **ข้าม key ที่ตายแล้วทันที** แทนที่จะเสียเวลา backoff 20-90 วินาทีกับ key ที่เครดิตหมด
  (แยกระหว่าง "ยิงถี่เกินไป" ซึ่งรอแล้วหาย กับ "เครดิตหมด/key ผิด" ซึ่งรอไปก็ไม่หาย)
- **ภาพที่ล้มเหลวไม่ทำให้ทั้งงานพัง** — จดไว้แล้วไปใบถัดไป รันซ้ำได้โดยของที่สำเร็จแล้วไม่ต้องจ่ายใหม่
- **จำสถานะ key ข้ามการรัน** (`~/.cache/weird-stories/keys.json`) — ไม่ต้องเสียเวลายิงใส่ key
  ที่เครดิตหมดใหม่ทุกครั้งที่รันคำสั่ง ครบ 6 ชั่วโมงค่อยลองใหม่เผื่อเติมเครดิตแล้ว
- **ล็อกเสียงที่อนุมัติแล้ว** (`gen_voice.py --approve`) — กันการอัดเสียงใหม่โดยไม่ตั้งใจ
  ตอนแก้คลิปรอบสอง รอบสาม

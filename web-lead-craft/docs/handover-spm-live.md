# spm-live — เว็บไซต์จริงของ Scientific Pest Management (Thailand)

`sites/spm-live/` เป็นเว็บจริง ไม่ใช่เดโม่ แยกคนละโฟลเดอร์กับ `sites/spm-pest*`
ซึ่งเป็นเดโม่ 4 สีที่ใช้เสนอตอนแรก **อย่าแก้ที่เดโม่แล้วคิดว่าแก้เว็บจริงแล้ว**

สร้างจากข้อมูลที่บริษัทส่งมา 2026-08-24: โบรชัวร์ 6 หน้า, ไฟล์ Word โครงเนื้อหา 7 ส่วน,
รูปถ่าย 20 ภาพ, และรายละเอียดติดต่อ

## ⛔ โดเมน — อ่านก่อนแตะ DNS

`spm.com` **เป็นของบริษัทจริง และมีอีเมลบริษัทวิ่งอยู่** ตรวจแล้วด้วย DNS:

| record | ค่า |
|---|---|
| NS | `ns-cloud-d1..d4.googledomains.com` (Google Cloud DNS) |
| MX | `mxtl-10..40.maildee.com` |
| SPF | `include:_spf.google.com include:truemail.co.th … a:outgoing.technologyland…` |
| A | `208.53.48.212` (เว็บเก่าที่ยังค้างอยู่) |

**กฎ: แก้ได้เฉพาะ A หรือ CNAME ของเว็บ ห้ามแตะ MX ห้ามย้าย nameserver**
ย้าย NS ไป Cloudflare เมื่อไหร่ MX หายทันที = `bangkok@spm.com` และ
`wattanathamm@spm.com` ดับ ซึ่งเป็นอีเมลที่ฝ่ายการตลาดใช้รับงานอยู่

ข้อจำกัดที่ตามมา: Google Cloud DNS ไม่รองรับ ALIAS/ANAME ที่ apex ดังนั้น
`spm.com` เปล่า ๆ ชี้ตรงมา Cloudflare Pages ไม่ได้ ทางที่ปลอดภัยที่สุดคือ
ใช้ `www.spm.com` เป็น CNAME ไป `<project>.pages.dev` แล้วให้ apex redirect
มาที่ www — ซึ่งต้องคุยกับคนที่ดูแล DNS ของบริษัท

## 🔴 ฟอร์มยังไม่ส่งจริง

`FORM_ENDPOINT` ใน `src/head.html` ยังว่าง = โหมดเดโม่ กดส่งแล้วขึ้น
"ส่งเรียบร้อย" แต่ **ไม่มีอะไรถูกส่งไปไหนเลย**

รับได้ตอนเป็นลิงก์ `pages.dev` ให้ลูกค้าดู แต่ **ห้ามขึ้นโดเมนจริงก่อนต่อ Worker**
ไม่งั้นลูกค้าของเขากรอกฟอร์มแล้วหายเงียบ ซึ่งเป็นสิ่งที่แย่ที่สุดที่เว็บนี้ทำได้

### ต่อทางไหน — อีเมล

Worker รองรับสองช่องทางแล้ว (LINE / อีเมล / ทั้งคู่) **เจ้านี้เลือกอีเมล**

เหตุผลไม่ใช่เรื่องเทคนิค แต่เป็นเรื่อง**ใครต้องลงมือ**: ทาง LINE ต้องให้บริษัท
เข้า LINE OA Manager เปิด Messaging API แล้วไปขุด `lineTo` (userId/groupId)
จาก LINE Developers Console ซึ่งฝ่ายการตลาดที่ไม่เคยเข้าหน้านั้นจะติดตั้งแต่ขั้นแรก
ส่วนอีเมล **ไม่ต้องขออะไรจากบริษัทเลยสักอย่าง** ปลายทางได้มาแล้ว
(`bangkok@spm.com`, `wattanathamm@spm.com` — ฝ่ายการตลาดดูแลเอง) และบัญชีผู้ส่ง
เป็นของเรา

ขั้นตอน:

1. สมัคร Resend, verify `shopdashth.com` (DNS 3 บรรทัดบนโดเมน**ของเรา**)
2. `wrangler secret put RESEND_KEY` และ `EMAIL_FROM`
3. ใส่ origin ของเว็บลง SITES secret พร้อม `emailTo` สองที่อยู่
4. `w.FORM_ENDPOINT = 'https://wlc-form.<subdomain>.workers.dev/'` ใน `src/head.html`
   แล้ว build ใหม่
5. กรอกฟอร์มจริงหนึ่งใบ **แล้วดูให้เห็นกับตาว่าเข้ากล่องจดหมาย**

> **ส่งจากโดเมนของเรา ไม่ใช่ `@spm.com`** — SPF ของ spm.com มี `include:` อยู่ 4 อัน
> การไปแก้เพื่อให้เราส่งในนามเขาได้ ถ้าพลาดคืออีเมลทั้งบริษัทเขาล่ม ไม่คุ้มเลย
> ชื่อผู้ส่งเป็นของเรา แต่ **Reply-To เป็นอีเมลของคนที่กรอกฟอร์ม** ซึ่งเป็นสิ่งที่
> ฝ่ายการตลาดต้องการจริง ๆ อยู่แล้ว

**เตือนไว้ล่วงหน้า** อีเมลฉบับแรก ๆ จากโดเมนใหม่มักตกกล่อง junk ของเมลบริษัทไทย
บอกฝ่ายการตลาดให้เช็ก junk แล้ว whitelist ในสัปดาห์แรก ไม่งั้นจะสรุปกันว่า "ฟอร์มไม่ทำงาน"

**LINE เติมทีหลังได้** ถ้าวันไหนบริษัทเปิด Messaging API แล้ว เติม `lineToken`
กับ `lineTo` ลงใน entry เดิมของ SITES **บรรทัดเดียว ไม่ต้องแก้โค้ด ไม่ต้อง deploy**
แล้วงานจะเข้าทั้งสองทาง

### จุดที่ไฟล์ Word ขัดกับไฟล์ตรวจภาษา

## ช่องอีเมลในฟอร์ม — ใส่เพราะ Reply-To

ฟอร์มมีช่อง **อีเมล (ไม่บังคับ)** เพิ่มมาแล้ว อยู่ถัดจากเบอร์โทร

ถ้าคนกรอกใส่มา Worker จะตั้งเป็น `Reply-To` ของอีเมลแจ้งเตือน **ฝ่ายการตลาดกด
reply ใน Outlook ที่เปิดอยู่แล้ว แล้วมันวิ่งไปหาคนกรอกเลย** ไม่ต้องก๊อปที่อยู่
สำหรับงาน B2B ที่ต้องส่งใบเสนอราคาต่อ นี่คือความต่างระหว่าง "รับงานได้" กับ
"ต้องพิมพ์ใหม่ทุกครั้ง"

**เบอร์โทรยังเป็นช่องบังคับช่องเดียวเหมือนเดิม** อีเมลเป็นของแถม ไม่ใช่ด่าน

ลงเป็น **ข้อความล้วน ไม่ใช้โลโก้** เพราะโลโก้เป็นเครื่องหมายการค้าที่ต้องขออนุญาต

คัดจากโบรชัวร์ที่บริษัทส่งมา ระบุไว้ว่า *"Actual letters received"*
**แต่โบรชัวร์เก่า** — หน้าเดียวกันมีคำรับรองจาก "Richard Ellis (Thailand)"
ซึ่งเปลี่ยนชื่อเป็น CBRE ตั้งแต่ราวปี 2549 แปลว่าเอกสารนี้อายุ 15–20 ปี

ที่เลือกมา 3 อัน (Shangri-La, Sheraton Grande Sukhumvit, The Pizza) ยังใช้ชื่อเดิม
แต่ **ตัวบุคคลน่าจะย้ายไปนานแล้ว** ต้องถามบริษัทว่า
1. ยังมีจดหมายต้นฉบับไหม
2. ยินดีให้ลงชื่อผู้เขียนหรือไม่ หรือจะตัดชื่อเหลือแค่ชื่อองค์กร


**ทำไมไม่ใช้รูปที่ลูกค้าส่ง** รูป QR ที่แคปจากมือถือคือภาพ JPEG หลายร้อย KB
ที่ต้องวิ่งไปหาผู้เข้าชมทุกคน คมที่ขนาดเดียว และพอเบราว์เซอร์ย่อลงบนมือถือ
**มันสแกนไม่ติด** — QR ต้องการขอบคมชัด รหัสเดียวกันวาดเป็น SVG หนัก 4 KB
คมทุกขนาด และรับสีจากธีมได้

สคริปต์ตั้งค่า error correction ระดับ H เพราะ QR บนเว็บมักถูกถ่ายจากจอด้วยมือถือ
ในมุมเอียง ความซ้ำซ้อนที่เพิ่มมาคือสิ่งที่ทำให้ยังอ่านออก

**เอาลิงก์มาจากไหน** ในแอป LINE OA → หน้า "เพิ่มเพื่อน" จะมี URL `https://lin.ee/…`
หรือกดค้างที่รูป QR แล้วเลือกคัดลอกลิงก์

**สคริปต์ถอดรหัส QR ที่ตัวเองเพิ่งวาดกลับมาเทียบก่อนเขียนไฟล์เสมอ** ถ้าอ่านกลับไม่ตรง
มันจะหยุดและไม่เขียนอะไรเลย เพราะ QR ที่เข้ารหัสผิดหน้าตาเหมือน QR ที่ถูกทุกประการ
กว่าจะรู้คือตอนลูกค้าส่องมือถือแล้วไม่ขึ้นอะไร (ต้องมี `pip install opencv-python-headless`
ไม่งั้นข้ามการตรวจ) ตอนใส่ `@560ipaso` ตรวจแล้ว: อ่านกลับได้ตรงทั้งขนาดบนคอม 132px
และบนมือถือ 104px

## ปุ่มลอยล่างจอ = โทร + LINE

เปลี่ยนจาก [โทร] [ขอสำรวจฟรี] เป็น **[โทร] [แอดไลน์]** ตามที่ผู้ประกอบการเลือก
เหตุผลเพิ่มเติมที่ทำให้เป็นการตัดสินใจที่ถูก: **ฟอร์มยังไม่ส่งจริง** (ดูหัวข้อด้านบน)
ปุ่มที่เด่นที่สุดบนจอมือถือจึงไม่ควรพาไปที่ทางตัน

ฟอร์มยังอยู่ในหน้าและยังเข้าถึงได้จากปุ่ม CTA อื่น ๆ ทั้งหน้า

## สิ่งที่ต่างจากเดโม่

เดโม่ตั้งใจไม่ใช้รูปเลย เพราะตอนนั้นไม่มีรูปของบริษัท และรูปแมลงจะไล่ลูกค้า
ตอนนี้มีรูปจริงของทีมงานแล้ว เว็บจึงเปลี่ยนไปมาก:

- `.gear` เดิมเป็นภาพเครื่องดักแมลงที่วาดด้วย CSS → เปลี่ยนเป็น IPM + PERMA-KILL™ พร้อมรูป 2 ใบ
- `#standard` เดิมเป็นใบรายงานที่วาดขึ้น → เปลี่ยนเป็นรูปจริง + ตราการรับรอง
- เพิ่มใหม่ 3 ส่วน: `#work` (แกลเลอรี), `.clients`, `#words`
- ธีมเปลี่ยนจากเขียว-ครีม เป็นน้ำเงินกรมท่า + ฟ้าแบรนด์ ตามที่ลูกค้าขอ (อ้างอิง web-clean-demo2)

## บั๊กที่เจอระหว่างทำ (แก้ที่ตัวเครื่องมือแล้ว)

`tools/images.mjs` เขียน `src="…-1200.webp"` เสมอ ทั้งที่ `buildDerivatives()`
ไม่ยอมขยายรูปเกินต้นฉบับ **รูปต้นฉบับที่แคบกว่า 1200px จึงพังทุกใบ** เดโม่เดิม
ไม่เจอเพราะรูปทุกใบกว้างเกิน 1200 พอดี รูปจากมือถือของลูกค้าไม่ใช่

แก้ด้วย `availableWidths()` ที่ทั้งตัวเขียนไฟล์และตัวเขียน HTML เรียกใช้ร่วมกัน
จึงขัดแย้งกันไม่ได้ และเพิ่มความกว้างของต้นฉบับเข้าไปด้วยเมื่อมันอยู่ระหว่างสองขั้น
รูป 720px จึงเสิร์ฟที่ 720 ไม่ตกไป 480

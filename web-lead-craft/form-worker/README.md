# form-worker — ตัวรับฟอร์มของเว็บลูกค้าทุกเจ้า

เว็บที่เราทำเป็นไฟล์นิ่ง ๆ บน Cloudflare Pages ไม่มีเซิร์ฟเวอร์อยู่หลังบ้าน
**ฟอร์มติดต่อจึงไม่มีที่ให้ส่งไป** ตัวนี้คือที่ให้ส่ง — รับฟอร์มจากเว็บลูกค้า
แล้วส่งต่อเข้า **LINE OA และ/หรืออีเมล** ของลูกค้ารายนั้นทันที

**Worker ตัวเดียวใช้กับลูกค้าทุกเจ้า** เพิ่มลูกค้าใหม่ = แก้ secret ไม่ต้อง deploy ใหม่

```
เว็บลูกค้า (Cloudflare Pages)  →  Worker ตัวนี้  →  LINE OA ของลูกค้า
     ฟอร์ม + honeypot              เช็ก origin     └→  อีเมลของลูกค้า
                                   กรอง + จัดรูปแบบ      (เลือกอย่างใดอย่างหนึ่ง
                                   ยิงพร้อมกันทุกช่อง      หรือทั้งสองอย่าง)
```

ไม่มีการเก็บข้อมูลไว้ที่ Worker เลย — ส่งต่อแล้วจบ ไม่มี KV ไม่มีฐานข้อมูล
ซึ่งเป็นสิ่งที่เขียนในหน้านโยบายความเป็นส่วนตัวได้ตรง ๆ

## ค่าใช้จ่าย

| | ฟรีถึง |
|---|---|
| Cloudflare Workers | 100,000 request/วัน — ฟอร์มร้านหนึ่งใช้ไม่ถึงร้อย |
| Resend (อีเมล) | 3,000 ฉบับ/เดือน · 100 ฉบับ/วัน |
| LINE Messaging API | นับรวมในโควตาข้อความของแพ็กเกจ OA ที่ลูกค้าใช้อยู่ |

## เลือกช่องทางไหนให้ลูกค้า

**ตัวชี้ขาดไม่ใช่ว่าอันไหนดีกว่า แต่คือลูกค้าต้องลงมือทำเองแค่ไหน**

| | LINE | อีเมล |
|---|---|---|
| โค้ดฝั่งเรา | มีอยู่แล้ว | มีอยู่แล้ว |
| ลูกค้าต้องเข้าระบบอะไรบ้าง | LINE OA Manager + LINE Developers Console | **ไม่ต้องเลย** — ขอแค่ที่อยู่อีเมล |
| ของที่ต้องขอ | token + `lineTo` (หายาก) | อีเมล 1–2 ที่อยู่ |
| ตอบกลับลูกค้าปลายทาง | ก๊อปเบอร์ไปโทร | กด reply ได้เลย (ดู Reply-To ข้างล่าง) |
| เก็บเป็นหลักฐาน / forward ต่อ | ลำบาก | ปกติของอีเมล |
| ข้อควรระวัง | ข้อความเลื่อนหายในแชทที่คนคุยเยอะ | ฉบับแรก ๆ มักตกกล่อง junk — บอกลูกค้าให้ whitelist |

**ค่าเริ่มต้นคืออีเมล** ถ้าลูกค้ามี LINE OA อยู่แล้วและอยากได้เด้งเข้ามือถือด้วย
ค่อยเติม LINE เพิ่มทีหลัง เป็นการแก้ `sites.json` บรรทัดเดียว ไม่ต้องแก้โค้ด

## Deploy ครั้งแรก (ทำครั้งเดียว)

```bash
cd web-lead-craft/form-worker
npx wrangler login                  # เปิดเบราว์เซอร์ให้ล็อกอิน Cloudflare
npx wrangler deploy                 # ได้ URL: https://wlc-form.<subdomain>.workers.dev
```

จำ URL ที่ได้ไว้ — ต้องเอาไปใส่ในเว็บลูกค้าทุกเว็บ

### ตั้งค่าอีเมล (ทำครั้งเดียว ใช้กับลูกค้าทุกเจ้า)

บัญชีนี้เป็น **ของเรา ไม่ใช่ของลูกค้า** ลูกค้าไม่ต้องยุ่งด้วยเลย

1. สมัคร [resend.com](https://resend.com) แล้ว **verify โดเมนของเราเอง** (`shopdashth.com`)
   — เอา DNS 3 บรรทัดที่เขาให้ไปใส่ใน Cloudflare
2. ออก API key
3. ใส่เป็น secret สองตัว:

```bash
npx wrangler secret put RESEND_KEY      # re_xxxxxxxx
npx wrangler secret put EMAIL_FROM      # เช่น: Web Lead Craft <leads@shopdashth.com>
```

> **ส่งจากโดเมนของเรา ไม่ใช่ของลูกค้า** — การส่งในนาม `@ลูกค้า.com` ต้องไปเติม
> `include:` ใน SPF ของเขา ซึ่งถ้าพลาดคืออีเมลทั้งบริษัทเขาล่ม ไม่คุ้มกันเลย
> ชื่อผู้ส่งเป็นของเราแต่ **Reply-To เป็นของลูกค้าปลายทาง** ซึ่งเป็นสิ่งที่ต้องการจริง ๆ

## เพิ่มลูกค้าใหม่ (ทำทุกครั้งที่รับงาน)

**1. ขอของจากลูกค้า** — ขึ้นกับช่องทางที่เลือก

*ถ้าเป็นอีเมล* — ขอแค่ที่อยู่อีเมลที่มีคนดูจริง ใส่ได้หลายที่อยู่

*ถ้าเป็น LINE* — สามอย่างนี้ลูกค้าต้องเป็นคนทำ เราทำแทนไม่ได้

| ต้องได้ | เอามาจากไหน |
|---|---|
| LINE Official Account | ลูกค้าสมัครเองที่ `manager.line.biz` ฟรี · **ใช้ LINE ส่วนตัวไม่ได้** |
| Channel Access Token | `developers.line.biz` → Messaging API → Issue token (long-lived) |
| userId หรือ groupId ปลายทาง | ดูวิธีหาข้างล่าง |

**หา `lineTo` ยังไง** — วิธีที่ง่ายที่สุดคือสร้างกลุ่ม LINE ของร้าน เชิญ OA เข้ากลุ่ม
แล้วอ่าน `groupId` จาก webhook event ตอนแรก (ตั้ง webhook ชั่วคราวที่ `webhook.site` ก็ได้)
ข้อดีของการส่งเข้ากลุ่มคือ **พนักงานหลายคนเห็นพร้อมกัน** ไม่ผูกกับมือถือเครื่องเดียว

**2. เพิ่มเข้า secret**

```bash
cp sites.example.json sites.json     # sites.json อยู่ใน .gitignore
# แก้ sites.json ใส่ origin จริงของลูกค้า + ช่องทางที่เลือก
npx wrangler secret put SITES < sites.json
```

> **key คือ origin ของเว็บ ตรงตัวที่เบราว์เซอร์ส่งมา** — `https://ชื่อโดเมน` ไม่มี `/` ปิดท้าย
> ถ้าเว็บเปิดได้ทั้ง `example.com` และ `www.example.com` ต้องใส่ **ทั้งสองอัน**
> origin ที่ไม่อยู่ในลิสต์จะโดนปฏิเสธ 403 — นั่นคือสิ่งที่กันคนอื่นมายืมฟอร์มเราส่งสแปม

**3. ชี้เว็บลูกค้ามาที่ Worker** — แก้ `src/head.html` ของเว็บนั้นบรรทัดเดียว

```js
w.FORM_ENDPOINT = 'https://wlc-form.<subdomain>.workers.dev/';
```

ปล่อยว่าง = ฟอร์มแค่ทำท่าส่ง (โหมดเดโม่) แล้ว build ใหม่ตามปกติ

**4. ทดสอบก่อนส่งมอบ** กรอกฟอร์มจริงบนเว็บที่ deploy แล้ว แล้วดูว่าเข้าปลายทางจริง
ถ้าไม่เข้า เปิด `npx wrangler tail` ดู log สด ๆ ได้เลย

## เว็บที่มีหลายฟอร์ม — แยกปลายทางตามฟอร์ม

เว็บหนึ่งมีได้หลายฟอร์ม (เช่น SPM: ขอสำรวจ → ฝ่ายการตลาด, สมัครงาน / แฟรนไชส์ → HR)
หน้าเว็บส่ง `<input type="hidden" name="form" value="job">` มา แล้ว Worker หา
`forms.job` ใน entry ของเว็บนั้น **ฟอร์มบอกได้แค่ชื่อ ปลายทางยังมาจาก SITES เสมอ**

```json
"https://spm.com": {
  "name": "Scientific Pest Management",
  "emailTo": ["bangkok@spm.com", "wattanathamm@spm.com"],
  "forms": {
    "job":       { "label": "ใบสมัครงาน",   "emailTo": ["hr.th@spm.com"], "attachPdf": true },
    "franchise": { "label": "สนใจแฟรนไชส์", "emailTo": ["hr.th@spm.com"] }
  }
}
```

- ค่าใน `forms.<ชื่อ>` **ทับ** ค่าของเว็บ ที่ไม่ได้เขียนก็ใช้ของเว็บ (เช่น `emailFrom`)
- `label` ขึ้นเป็นหัวเรื่องอีเมลแทน "ลูกค้าใหม่" — HR แยกใบสมัครออกจากลูกค้าได้ก่อนเปิด
- ชื่อฟอร์มที่ไม่รู้จัก (หรือไม่ส่งมา) **ตกไปที่ปลายทางหลักของเว็บ** ไม่ทิ้ง
- entry ของเว็บเอง**ต้องมีช่องทางส่งที่ครบ** — `forms` แค่เปลี่ยนปลายทาง

### แนบ CV (PDF) — `attachPdf: true`

ฟอร์มที่ตั้ง `attachPdf` รับไฟล์ช่อง `file` ได้หนึ่งไฟล์ ส่งเป็น multipart
แล้ว Worker แนบไปกับอีเมล — **ฟอร์มอื่นของเว็บเดียวกันส่งไฟล์มาก็ถูกทิ้ง**

| เช็ก | ถ้าไม่ผ่าน |
|---|---|
| ไม่เกิน 4MB | `413 file_too_large` |
| เป็น PDF จริง (ดูจากไบต์ `%PDF-` ไม่ใช่ชื่อไฟล์) | `415 file_not_pdf` |
| ปลายทางมีอีเมล (LINE แนบ PDF ไม่ได้) | `500 server_misconfigured` |

ชื่อไฟล์ถูกล้างเหลือแค่ตัวอักษร (ไทยได้) ตัวเลข ช่องว่าง `._()-` แล้วบังคับลงท้าย `.pdf`

**เรื่อง CPU ของแพ็กเกจฟรี** — วัดบน workerd แล้ว ไฟล์ 4MB ใช้ CPU ราว 10ms
ซึ่งเท่ากับเพดานต่อ request ของ Workers ฟรีพอดี CV ทั่วไป (≤ 1–2MB) ใช้แค่ส่วนเดียว
ถ้า log ขึ้น `Exceeded CPU` บ่อย ๆ คืออัปเกรด Workers Paid (5 USD/เดือน, เพดาน 30 วินาที)
— ไม่ต้องแก้โค้ด ระหว่างนี้คนสมัครจะเห็นกล่องแดงพร้อมอีเมล HR ไม่ใช่หายเงียบ

## Reply-To — เหตุผลที่มีช่องอีเมลในฟอร์ม

ถ้าคนกรอกใส่อีเมลมาด้วย Worker จะตั้งเป็น `Reply-To` ของอีเมลที่ส่งถึงลูกค้า
**ลูกค้ากด reply ในโปรแกรมเมลที่เขาเปิดอยู่แล้ว แล้วมันวิ่งไปหาคนกรอกเลย**
ไม่ต้องก๊อปที่อยู่ ไม่ต้องเปิดหน้าต่างใหม่

ถ้าอีเมลที่กรอกมาผิดรูปแบบ **จะตัด Reply-To ทิ้งแต่ยังส่งอยู่** — เพราะ Resend
ปฏิเสธทั้งฉบับถ้า Reply-To เพี้ยน แล้วใบสั่งงานจะหายไปเพราะลูกค้าพิมพ์ตกจุดเดียว
สิ่งที่เขาพิมพ์มายังอยู่ในเนื้ออีเมลเหมือนเดิม

## กันสแปม

| ชั้น | ทำอะไร |
|---|---|
| origin allowlist | เว็บที่ไม่รู้จักยิงเข้ามาไม่ได้ |
| honeypot (`wlc_hp`) | ช่องที่คนมองไม่เห็น บอทกรอก = ทิ้งเงียบ ๆ ตอบ 200 ให้บอทคิดว่าสำเร็จ |
| timing | กรอกเสร็จเร็วกว่า 2.5 วินาที = ไม่ใช่คน ทิ้งเหมือนกัน |
| field allowlist | รับเฉพาะช่องที่เรารู้จัก ที่เหลือทิ้ง — ฟอร์มนี้ส่งต่ออะไรก็ได้ไม่ได้ |

ช่องที่ Worker รับ (นอกจากนี้ทิ้งทั้งหมด):
`position` `name` `company` `tel` `email` `education` `province` `type` `pest` `size` `date` `slot` `note`
(+ `form` เลือกปลายทาง, `file` ไฟล์แนบ บนฟอร์มที่เปิด `attachPdf`)
— ถ้าฟอร์มของเว็บใหม่ต้องใช้ชื่อช่องที่ไม่มีในลิสต์นี้ ต้องเพิ่มใน `LIMITS`
และ `LABELS` ใน `src/worker.mjs` ก่อน ไม่งั้นข้อมูลจะหายเงียบ ๆ

**ชื่อช่อง honeypot ห้ามเป็น `website` / `url` / `email2`** เพราะ autofill ของเบราว์เซอร์
อาจกรอกให้ลูกค้าจริงโดยที่เขาไม่รู้ตัว แล้วใบสั่งงานจริงจะหายเงียบทุกใบ

ปลายทางทั้งหมด (`to`, `lineTo`) มาจาก secret ฝั่งเราเสมอ **ไม่เคยมาจากตัวฟอร์ม** —
ถ้ามาจากฟอร์มได้ ฟอร์มนี้ก็คือเครื่องส่งเมลฟรีของใครก็ได้

ถ้าวันไหนโดนสแปมหนักจริงจนสองชั้นนี้เอาไม่อยู่ ค่อยเพิ่ม Cloudflare Turnstile
(ฟรี) แต่มันจะเพิ่มสคริปต์ภายนอกและคุกกี้ ซึ่งต้องไปแก้หน้า PDPA ด้วย — อย่าใส่ก่อนจำเป็น

## เทสต์

```bash
node --test form-worker/test/worker.test.mjs      # กฎทั้งหมดของ Worker (48 เคส)
```

เทสต์ยิงเข้า handler ตัวจริงที่ deploy ไม่ใช่โค้ดจำลอง มีแต่ขา request ออก
(`api.line.me` กับ `api.resend.com`) ที่ถูกสตับ

ทดสอบทั้งสายตั้งแต่เบราว์เซอร์ (ต้องเปิดสามอย่างพร้อมกัน):

```bash
# 1. LINE ปลอม
node form-worker/test/fake-line.mjs 8788 /tmp/line-log.jsonl &

# 2. Worker ตัวจริงบน workerd
cd form-worker && npx wrangler dev --port 8787 --local \
  --var SITES:'{"http://127.0.0.1:4321":{"name":"ทดสอบ","lineToken":"t","lineTo":"U1","lineApi":"http://127.0.0.1:8788"}}' &

# 3. เบราว์เซอร์จริงกรอกฟอร์มจริง
node form-worker/test/e2e.mjs sites/demo-cleaning /index.html http://127.0.0.1:8787/ /tmp/line-log.jsonl
```

`lineApi` กับ `emailApi` มีไว้ให้เทสต์ชี้ไปเซิร์ฟเวอร์ปลอมเท่านั้น ของจริงไม่ต้องใส่

## เมื่อส่งไม่สำเร็จ

| สถานะ | แปลว่า | เว็บทำอะไร |
|---|---|---|
| `200 ok` | **มีอย่างน้อยหนึ่งช่องทางยืนยันว่าส่งถึงแล้ว** | ขึ้นกล่องเขียว "ได้รับคำขอแล้ว" |
| `502 delivery_failed` | ยิงครบทุกช่องทางแล้ว พังหมด | ขึ้นกล่องแดง + เบอร์โทรให้กดแทน |
| `500 server_misconfigured` | ลูกค้ารายนี้ **ไม่มีช่องทางส่งที่ตั้งค่าครบเลย** | ขึ้นกล่องแดงเหมือนกัน |

ลูกค้าที่ตั้งค่าไม่ครบต้องพัง **ทุกครั้งและดังๆ** ไม่ใช่ตอบ 200 แล้วทิ้งใบสั่งงาน —
`npx wrangler tail` จะบอกว่าขาดอะไร

**ห้ามแก้ให้ขึ้นว่าสำเร็จเมื่อส่งไม่ได้** — ใบสั่งงานที่หายเงียบคือลูกค้าที่เสียไปโดยร้านไม่มีทางรู้
